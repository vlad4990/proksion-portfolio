# hh/ — поиск работы для Кристины (hh.ru)

Исследование рынка «графический дизайнер» (Москва) + рабочие документы для отклика. Не часть сайта PROKSION.

## Структура

```
hh/
  resume.htm               ← исходное резюме, экспорт с hh.ru (обновлено 10.02.2026) — НЕ трогать, это baseline
  resume-improved.md       ← РАБОЧИЙ: финальное резюме v3 (13.09.2026) — тексты по полям hh без плейсхолдеров + обоснования
  resume.html              ← то же резюме самостоятельным HTML (бренд-шрифты вшиты base64, светлая тема, печать A4 в 2 страницы)
  Torgovtseva-Kristina-CV.pdf ← PDF из resume.html (headless Chrome) — для отправки напрямую и кнопки CV/PDF на сайте
  photo-cv.jpg             ← кадр портрета для резюме (559×672, q62) — ИСХОДНИК того, что вшито в resume.html base64; годится и для фото профиля hh
  vacancies-shortlist.md   ← РАБОЧИЙ: актуальный шорт-лист (выдача hh живёт ~1–1.5 недели!)
  research/
    _method/
      snippets.js          ← ПРОВЕРЕННЫЙ JS сбора через Chrome MCP (парсеры, агрегаты, фильтры) — использовать буквально
      compare.py           ← сравнение двух snapshot.json → markdown-таблицы динамики
    YYYY-MM-DD/            ← датированные снапшоты исследования рынка
      market-analysis.md   ← полный отчёт на дату (с разделом динамики к прошлому снапшоту)
      snapshot.json        ← машиночитаемые агрегаты — ОСНОВА ДЛЯ СРАВНЕНИЯ ДИНАМИКИ
      dynamics.md          ← вывод compare.py против предыдущего снапшота
      shortlist.md         ← копия шорт-листа на дату (вакансии умирают — это фиксация)
      raw-main.json, raw-remote.json ← сырые выгрузки субагентов (для перепроверки)
```

Пересборка HTML→PDF: `Google Chrome --headless=new --no-pdf-header-footer --print-to-pdf=… file://…/resume.html`.

Правка шапки **14.09.2026** (по разметке заказчика на макете): имя и фамилия — в одну строку, роль — в одну строку, блок зарплаты («100 000 ₽» + «на руки») из макета убран, формат работы («удалённо · полная или проектная занятость») вынесен строкой под роль, справа добавлен портрет (`photo-cv.jpg`, кроп из `front/src/assets/about-me-photo.webp`). Шапка и контакты обёрнуты в грид `.masthead` (`minmax(0, 1fr) 48mm`, зазор 6mm): левая колонка — имя/роль/формат + контакты **в 2 столбца × 3 строки**, правая — портрет на всю высоту блока (`align-self: stretch` + `object-fit: cover`, без `aspect-ratio` — высоту задаёт левая колонка). Зарплата остаётся полем профиля hh (`resume-improved.md`, 100 000 ₽) — из PDF она убрана только визуально. Портрет вшит в HTML как **JPEG** base64: webp Chrome кладёт в PDF несжатым (678 КБ против 238 КБ) — при замене фото формат не менять.

Правки текста **14.09.2026**: фраза «Нейросети — повседневный рабочий инструмент, а не эксперимент.» заменена на «**Свободное владение нейросетями.**», из навыков убраны **Ретушь, Типографика, Полиграфия, Допечатная подготовка** (в тексте «О себе» полиграфический бэкграунд остался). Синхронно поправлен `resume-improved.md` — это тот же контент для полей hh. Футер сведён к одной кликабельной ссылке `proksion.ru`, прижатой вправо (ФИО/роль и дата обновления убраны).

⚠️ **Грабли шапки:** колонка текста обязана быть `minmax(0, 1fr)`, а не `1fr` — иначе `min-content` строки роли (у неё `white-space: nowrap`) распирает грид, и портрет уезжает за правое поле страницы (было +74px на экране, в PDF — за край поля). По той же причине кегль роли снижен до 10.5pt: «Графический дизайнер / AI-дизайнер — SMM, digital-креативы» в одну строку требует ~454px, а рядом с портретом 48mm остаётся ~470px. Увеличивать портрет дальше можно только вместе с уменьшением этой строки.

## Как повторить прогон (методология, соблюдать для сопоставимости)

0. **Дешёвый способ (проверен 2026-09-11):** два Sonnet-субагента параллельно — «основная выдача + глубокая выборка + живость прошлого шорт-листа» и «удалённый пул + кандидаты + детали топ-кандидатов». Каждому: прочитать этот README и `_method/snippets.js`, создать СВОЮ вкладку, писать `raw-main.json` / `raw-remote.json` в новую папку снапшота. Потом собрать `snapshot.json` в схеме предыдущего и прогнать `python3 research/_method/compare.py research/<старый>/snapshot.json research/<новый>/snapshot.json > research/<новый>/dynamics.md`.
1. **Сбор — через Chrome (MCP), внутри страницы hh.ru** через `fetch` + `DOMParser` (api.hh.ru из браузера отдаёт 403; вывод javascript_tool ограничен ~1.5 КБ и блокируется при query-строках — копить данные в `window.*`, выгружать агрегаты).
2. **Источники** (все три, дедуп по id):
   - основная выдача: `https://hh.ru/vacancies/graficheskiy_dizayner` + `?page=N` (0-based, 50/стр);
   - удалёнка Москва: `.../graficheskiy_dizayner/udalennaya_rabota`;
   - удалёнка Россия: `/search/vacancy?text=графический дизайнер&area=113&work_format=REMOTE` (20/стр).
3. **Селекторы** (проверить, hh их меняет): карточка `[data-qa="vacancy-serp__vacancy"]`, тайтл `[data-qa="serp-item__title"]`, работодатель `[data-qa="vacancy-serp__vacancy-employer"]`; на странице вакансии — `[data-qa="vacancy-title"|"vacancy-salary"|"vacancy-experience"|"work-formats-text"|"skills-element"|"vacancy-description"]`. Зарплату в карточке искать как глубочайший элемент с `₽`.
4. **Нормализация зарплат**: к «на руки» (gross × 0.87), точка сравнения — середина вилки; только «от» → from, только «до» → to.
5. **Глубокая выборка**: каждая 6-я вакансия основной выдачи (~115 шт) — полные описания, key skills, формат работы. Считать те же метрики, что в `snapshot.json` (термины и регекспы — там же; осторожно с regex «ИИ» — «ии » матчит окончания русских слов).
6. **Результат**: новая папка `research/YYYY-MM-DD/` с теми же тремя файлами.

## Как сравнивать динамику

Сравнивать `snapshot.json` нового и старых снапшотов по секциям:
- `salary_net.overall` и `salary_net.by_experience["1-3 года"]` — сдвиг вилок (главное для Кристины);
- `remote_pool_277.salary_net` и доля удалёнки — растёт ли удалённый сегмент и его оплата;
- `deep_sample_113.tools_mentions` — динамика требований (особенно `ai_tools`, `figma`);
- `segments_by_title` — какие ниши растут/сжимаются (маркетплейсы, AI в названии);
- `deep_sample_113.requirements.portfolio` — жёсткость входного фильтра;
- `shortlist_vacancy_ids` — сколько прошлых вакансий ещё живы (мера скорости рынка).

В новом `market-analysis.md` добавлять секцию «Динамика с прошлого снапшота» с этим сравнением.
