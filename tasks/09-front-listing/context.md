# Context — 09 front-listing

## Цель в одной строке
Заменить статические заглушки листинга в публичном фронте на данные из реального API
(оба дерева desktop+mobile), сохранив masonry-раскладку и форму тайла.

## Опорные разделы спеки
- §8 (интеграция фронта), §7 (контракты public-api), §4 (URL).
- `front/CLAUDE.md`: листинг на `react-masonry-css`, двойное дерево, форма тайла `{id,src,w,h}`,
  skeleton-тон `--c-skeleton`, `loading="lazy"`/`decoding="async"`, `aspect-ratio` от `w/h`.

## Что уже есть
- Публичные эндпоинты (задача 03): `/api/categories...`, `/api/works...`, тайлы `{id,src,w,h}`.
- Во `/front` — `ProjectsScreen.tsx` (desktop) и `MobileProjects.tsx` (mobile) с **захардкоженными**
  массивами `GROUPS`/тайлов (см. `front/CLAUDE.md` — данные дублируются между файлами).

## Методология — SDD (Spec-Driven, без тест-ферст)
- Реализация строго по спеке + `front/CLAUDE.md`. Проверка корректности = `npm run build`
  (tsc strict) + визуальный чек-лист `verify.md`. Тесты не вводим (конвенция `/front`).

## Инварианты / ограничения
- **Двойное дерево**: правки в ОБОИХ — `ProjectsScreen.tsx` и `MobileProjects.tsx`.
- Не ломать masonry-контракт: тайл `{id,src,w,h}`, колонки `breakpointCols`, зазоры-токены.
  Форма данных уже CDN-ready (см. `front/CLAUDE.md`) — просто подменяем источник массивов на API.
- Бренд/токены — без новых hex; минимум зависимостей (никаких новых UI-либ в `/front`).
- Тайлы остаются кликабельными «заделом», но сам клик→модалка — задача 10 (здесь не обязателен).
- Картинки берём по URL из API (`/media/...`); пока реальных файлов нет — допустимы seed/placeholder.

## На что НЕ замахиваться
Модалка/карусель/роуты работы (задача 10), занавес-герой, выбор дерева, админка.
