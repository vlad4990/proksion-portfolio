# Task — 08 admin-ui

**Слой:** `/admin`. **Методология:** **TDD** (Vitest+RTL) для логики; UI — компонентно. Спека: §3, §7, §8.

## Цель
Полноценная админка: редактор может через UI создать категорию → подкатегорию → работу,
загрузить картинки, задать описание/cover/порядок — и это сразу видно на публичном сайте.

## Шаги

1. **Категории / подкатегории** — экраны со списком (shadcn `table`), формы создания/правки
   (`dialog`+`form`), удаление с подтверждением. Логика маппинга/валидации — TDD.
2. **Работы** — список работ подкатегории; форма работы: title, **описание** (textarea, при
   markdown — превью), выбор cover из загруженных картинок, удаление. TDD: валидация, маппинг.
3. **Загрузка картинок** — мультизагрузка в работу (`POST /admin/works/:id/images`) с
   индикатором прогресса и обработкой ошибок; редактирование alt, удаление, выбор cover.
   TDD: state machine загрузки (idle→uploading→done/error), очередь файлов.
4. **Сортировка (drag-n-drop)** — для категорий/подкатегорий/работ/картинок; по drop'у слать
   `reorder` (упорядоченный список id). TDD: функция вычисления нового порядка/payload.
5. **Связность** — после операций обновлять данные (refetch/инвалидция), показывать toast'ы
   успеха/ошибки.

## Требования
- Все вызовы — через API-клиент (07), `credentials:'include'` + CSRF-заголовок.
- Strict TS, без `any`. Доступ только за `RequireAuth`.
- Не менять серверные контракты (03/06). Несоответствие — фиксировать как замечание, не править API.

## Deliverables
Экраны категорий/подкатегорий/работ/картинок + drag-n-drop reorder + редактор описаний,
с тестами логики. `vitest` зелёный, `npm run build` зелёный, e2e-путь работает против `back`+`minio`.
