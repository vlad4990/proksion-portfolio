# Tasks — миграция PROKSION на Astro

**Статус: миграция завершена.** Все пять фаз (01–05) реализованы и провалидированы. Папка сохраняется как история миграции и reference на случай регрессий.

Пять фаз, каждая исполняется и проверяется отдельно. Контекст в каждой задаче — самодостаточный: новый разговор с Claude может выполнить её, не читая остальные файлы и не теребя `design-system/` целиком.

## Как пользоваться

Каждая фаза — отдельная папка с двумя файлами:

```
tasks/
├── 01-scaffold/
│   ├── task.md        ← сама задача: цель, контекст, deliverables, implementation notes
│   └── verify.md      ← чек-лист: ручные проверки в браузере + автоматические команды
├── 02-hero-curtain/
│   ├── task.md
│   └── verify.md
├── 03-about/
├── 04-projects/
└── 05-finish/
```

Рабочая процедура:

```
1. Открыть tasks/0N-name/task.md в Claude Code.
2. Скомандовать: «выполни всё, что написано в файле».
3. После завершения скомандовать: «сверься с tasks/0N-name/verify.md, пройди все пункты».
4. Прочитать отчёт, проверить лично визуальные пункты, починить недочёты.
5. Закоммитить и переходить к следующей фазе.
```

## Очерёдность

Фазы строго последовательные — каждая следующая опирается на каркас предыдущих.

| # | Фаза | Что появляется | Время |
|---|---|---|---|
| 01 | **Scaffold** | Astro в `/front`, токены, шрифты, Docker, пустые роуты | 2–4 ч |
| 02 | **Hero + Curtain** | Главная страница с занавесом, адаптив 360–1920 | 3–5 ч |

## Общие правила (применяются ко всем фазам)

Эти правила вынесены в каждый task-файл повторно, но держите их в голове глобально:

1. **Бренд — святое.** Все цвета/шрифты/иконки только из `design-system/`. Никаких новых hex'ов сверх перечисленных в `design-system/colors_and_type.css`. Никаких эмодзи. Никаких градиентов, drop-shadow, glass-морфизма. Подробно — `design-system/README.md` (раздел VISUAL FOUNDATIONS).

2. **Токены — single source of truth.** Все размеры/цвета/отступы — через `var(--...)`. Если нужного токена нет, добавьте его в `design-system/colors_and_type.css` (с переопределениями по @media для адаптива), а не в локальный CSS. Никаких inline-hex'ов в финальном коде.

3. **Bundle и скорость — приоритет.** Astro по умолчанию = 0 kb JS. React-острова (`client:load` / `client:idle`) — **только** для реально интерактивных кусков (Curtain, ProjectsSidebar+Grid, MobileTabBar-highlight). Всё остальное — `.astro` без `client:*`. Изображения — обязательно через `astro:assets` или эквивалент с responsive srcset и WebP/AVIF.

4. **Адаптив 360 → 1920**, дискретные сеты типографики через @media. Брейкпойнты: `--bp-xs 360`, `--bp-sm 480`, `--bp-md 768`, `--bp-lg 1024`, `--bp-xl 1280`, `--bp-2xl 1440`, `--bp-3xl 1920`. На каждом — отдельная композиция, не просто scale.

5. **TypeScript strict.** `tsconfig.json` с `strict: true`. Все компоненты типизированы, никаких `any`.

6. **Старый код — reference, не для копирования.** В `_legacy/` (создаётся фазой 01) лежит оригинальный экспорт из Claude design — читаем для понимания дизайн-решений, но не копируем код. Mobile-компоненты там — **не каноничны**, их доделывает фаза 02–05 «с пониманием», а не 1-в-1.

7. **Контент — заглушка.** Тексты для About и Contacts берём из `_legacy/AboutSection.jsx` и `_legacy/MobileContacts.jsx`. Для Projects — placeholder-плитки + 2 реальных миниатюры (как сейчас). Реальный контент проектов подвезётся позже.

8. **Backend пока нет.** Все API-вызовы из фазы 04 уходят через `front/src/lib/api.ts`, который сейчас возвращает stub-данные. Контракт API проектируем так, чтобы будущий `/back` мог быть прикручен подменой одного модуля.
