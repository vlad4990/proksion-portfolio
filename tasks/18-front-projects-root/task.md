# Task — 18 front-projects-root

**Слой:** `/front`. **Методология:** **SDD** (build + визуал по дизайну).
Спека: [`docs/projects-redesign.md`](../../docs/projects-redesign.md) §2.1–§2.2, §6.
Дизайн: фреймы `tVnqG` (desktop) / `N8NrSi` (mobile) в `front/1111.pen` (Pencil MCP).
Зависит от задач 14, 17.

## Цель

`/projects` (оба дерева) = hero + чипы-теги (`?tag=`) + секции категорий с витринами
трёх вариантов + футер. Сайдбар и глобальный «Показать ещё» удалены.

## Шаги

1. **Desktop `ProjectsScreen.tsx`** — переписать по фрейму `tVnqG`:
   - **Hero**: оверлайн, «ПРОЕКТЫ» + красный квадрат, подзаголовок (тексты — константы
     компонента); статы справа: «N+ РАБОТ В АРХИВЕ» (сумма `work_count` категорий),
     «N НАПРАВЛЕНИЙ» (число категорий), «3 ГОДА В КОММЕРЧЕСКОМ ДИЗАЙНЕ» (константа).
   - **Ряд фильтров**: `FilterChip`-ссылки: «ВСЕ <total>» → `/projects`,
     тег → `/projects?tag=<slug>` (активный — по query); справа «NN РАЗДЕЛОВ ↓»
     (NN = число категорий, клик — плавный скролл к первой секции через
     `smoothScrollTo` из `src/lib/scroll.ts`). Пустой `/tags` → ряд скрыт.
   - **Секции** (по категориям, порядок API): для каждой — данные из
     `useFeatured` + `CategoryNav`. Голова по варианту (полная — showcase,
     лёгкая — strip/cards; «ВСЕ РАБОТЫ ↗» → `/projects/<cat>`). Витрина:
     - `showcase`: Row A (hero-тайл ~60% ширины с пилюлей-подписью = `title`
       работы + колонка 2 тайлов) + Row B (4 тайла) — заполнять из списка
       витрины по порядку, лишние не рендерить, при нехватке — сокращать ряды
       (1 работа = только hero);
     - `strip`: один ряд фиксированной высоты (h380 при ≤4 работах, h230 при 5+);
     - `cards`: карточки (превью h340 + title + description работы + мета-ряд,
       «СМОТРЕТЬ КЕЙС ↗» → модалка работы); description = `FeaturedWork.description`.
     - Все тайлы витрин — `<Link>` на канонический `/projects/:cat/:sub/:slug`;
       обрезка `object-fit: cover`, `<picture>` avif/webp/jpg (thumb).
   - **Тег-режим** (`?tag=` в URL): в каждой секции вместо витрины —
     masonry-грид (`react-masonry-css`, текущие `BREAKPOINT_COLS`) работ
     категории с тегом (`useInfiniteWorks({category, tag})` — без сентинела,
     просто все страницы не нужны: грузить первую порцию 24; если работ больше —
     ссылка «ВСЕ РАБОТЫ ↗» уже ведёт в раздел). Секции с 0 совпадений скрыть;
     все секции по нулям → состояние «пусто» (текст + сброс на «ВСЕ»).
   - **Футер** — `<ProjectsFooter/>`; skeleton/error-состояния для категорий
     и витрин (тон `--c-skeleton`, без белых экранов).
2. **Mobile `MobileProjects.tsx`** — то же по фрейму `N8NrSi`: hero + статы в ряд;
   горизонтальный скролл чипов (без переноса, скрытый скроллбар); секции: Title
   Line + описание + мета-ряд; витрины: showcase = hero h240 + пары, strip =
   пары/тройки h110, cards = карточки в столбик; тег-режим — masonry 2 колонки;
   футер. Существующий фиксированный header-паттерн экрана сохранить.
3. **Роутинг/сео** — `App.tsx` не меняется (`/projects` уже смонтирован);
   `?tag=` читать через `useSearchParams`; `document.title` остаётся
   «Проекты — PROKSION».
4. **Чистка** — удалить мёртвый код старого экрана (сайдбар, `groupTo`,
   неиспользуемые стили) в обоих деревьях; `useProjects` оставить, если его ещё
   использует что-то живое, иначе выпилить вместе с кэшем (проверить импорты).

## Требования

- Strict TS; без новых зависимостей; только токены (включая новые из 17).
- Резервирование места: фиксированные высоты витринных слотов, aspect-ratio в
  masonry — скролл не прыгает.
- Оба дерева ведут себя одинаково (навигация, тег-режим, футер).

## Deliverables

Переписанные `ProjectsScreen` + `MobileProjects` (+ module.css), чистка мёртвого
кода. `npm run build` зелёный, визуальная сверка с фреймами пройдена.
`front/CLAUDE.md` обновлён (описание корневой страницы).
