# Task — 16 admin-ui-listing-content

**Слой:** `/admin`. **Методология:** **TDD** для логики (Vitest+RTL), компонентный
подход для разметки. Спека: [`docs/projects-redesign.md`](../../docs/projects-redesign.md)
§7 (+§5.5 — контракты мутаций). Зависит от задач 14, 15.

## Цель

Kristina управляет из админки всем контентом нового листинга: метаданные категории,
теги, разметка работ тегами, витрина раздела с порядком и hero-слотом.

## Шаги

1. **API-клиент** (TDD): функции мутаций по таблице из `context.md`
   (`updateCategoryMeta`, `createTag`/`updateTag`/`deleteTag`/`reorderTags`,
   `setWorkTags` — как часть PATCH работы, `setCategoryFeatured`) + чтение
   (`getTags`, `getFeatured`, `getWorksByCategory` — с учётом пагинации: выгребать
   страницы до `total`, работ на категорию немного). Обработка 400/401/403 —
   как в существующем клиенте.
2. **Форма категории** — добавить поля: `kicker`, `meta_role`, `period`
   (текстовые инпуты с подписями-примерами из дизайна: «КОММЕРЧЕСКАЯ ГРАФИКА»,
   «SMM · ПРОМО-ГРАФИКА», «2023 — 2026»), `description_long` (textarea),
   `display_variant` (select: «Витрина (hero + сетка)» / «Полоса тайлов» /
   «Карточки с текстом» — значения `showcase`/`strip`/`cards`).
   ⚠️ `NamedEntityDialog` общий с подкатегориями — расширять через
   проп-переключатель (или выделить `CategoryDialog`), подкатегории не трогать.
   Маппинг — в `forms/schemas.ts` по конвенции `emptyToNull` (пустая строка →
   null). Тест (по образцу `schemas.test.ts`): маппинг формы → тело запроса,
   в обе стороны.
3. **Экран «Теги»** — новый пункт навигации; таблица (title, slug, счётчик
   работ из `/tags`), создание (title, слаг генерится бэком; опционально явный),
   переименование, удаление (подтверждение, предупредить что тег снимется со
   всех работ), перестановка порядка (существующий reorder-механизм админки).
   Тесты: happy-path CRUD через мок fetch, конфликт слага (400) показывает
   ошибку.
4. **Теги в редакторе работы** — блок мультивыбора: все теги из `/tags`
   чипами/чекбоксами, текущий набор из `WorkDetailById.tag_ids` (или detail-
   эндпоинта, которым админка уже пользуется), сохранение — `tag_ids` в PATCH
   работы. Тест: переключение чипа меняет отправляемый набор целиком.
5. **Витрина категории** — на странице категории новый блок «Витрина раздела»:
   - упорядоченный список текущей витрины: `/featured` с `curated: true`;
     при `curated: false` (fallback) — пустое состояние с подсказкой
     «витрина не настроена — на сайте показываются первые работы раздела»;
   - добавление работ из списка работ категории (`getWorksByCategory` —
     превью-тамб + title), удаление из витрины, перестановка (вверх/вниз);
   - первая позиция помечена «HERO» (и подсказка: на корневой странице это
     большой тайл);
   - сохранение одним `setCategoryFeatured(categoryId, workIds)`; кнопка
     «Очистить витрину» → пустой массив.
   - Тест (RTL): перестановка меняет порядок в отправляемом `work_ids`;
     hero-метка следует за первым элементом.
6. **Полировка контракт-гэпа WorksPage** — тайлы теперь несут `slug`/`title`
   (задача 14): обновить `admin/src/lib/works-view.ts` (+ его тест), чтобы
   слаг/название брались из API, а не только из сессионного реестра — кнопка
   «Управление» становится доступной для всех видимых работ, а не только
   созданных в текущей сессии. Реестр оставить как источник для работ без
   картинок.
7. **Счётчики** — в таблице подкатегорий счётчик уже есть; проверить, что смена
   семантики `work_count` (видимые работы, задача 14) не сломала отображение,
   поправить подписи при необходимости («работ с картинками»).

## Требования

- Strict TS, без `any`; стиль и компоненты — существующие (shadcn/Tailwind);
  тексты русские.
- Все мутации шлют `X-Requested-With` (существующий транспорт), ошибки
  показываются пользователю (тосты/инлайн — как принято в проекте).
- `npm run build` (admin) и тесты зелёные.

## Deliverables

Обновлённые формы категории/работы, экран «Теги», блок «Витрина раздела»,
расширенный api-клиент + тесты. `cd admin && npm run build` и Vitest зелёные.
`docs/architecture.md` §8 (список экранов админки) дополнен.
