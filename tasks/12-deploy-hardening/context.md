# Context — 12 deploy-hardening

## Цель в одной строке
Довести инфраструктуру до прод-готовности: healthcheck'и/порядок запуска, секреты, непубличный
MinIO, HTTPS, кэш-заголовки, прод-доку, синхронизация `CLAUDE.md`+памяти и e2e-смоук.

## Опорные разделы спеки
- §2 (топология/volumes), §10 (безопасность), §11 (изменения в репо/env), §9 (бэкап/секрет rclone).

## Что уже есть (после задач 01–11)
- `caddy`+`back`+`minio` в compose; multi-stage Dockerfile; auth; admin-API/UI; публичный фронт
  с листингом+модалкой; бэкап/restore через rclone.

## Методология
- Инфра/финализация; без TDD. Корректность = `verify.md` (прод-подобный запуск + e2e-смоук).

## Что закрыть
- **Порядок/здоровье:** `depends_on: condition: service_healthy` (caddy←back,minio; back←minio);
  адекватные healthcheck'и и `restart: unless-stopped`.
- **Секреты:** `JWT_SECRET`, `ADMIN_PASSWORD_HASH`, `MINIO_*`, `S3_*`, токен облака — через
  `.env`/секреты/volume, не в образ и не в репо. `.env` в `.gitignore` (проверить).
- **MinIO:** наружу не публикуется (ни API, ни консоль); приложение ходит отдельным S3-ключом,
  не root (создать app-credentials). Public-read — только на `images/*`.
- **Caddy/HTTPS:** прод `SITE_ADDRESS=домен` → авто-TLS Let's Encrypt; кэш-заголовки на `/media/*`
  и `/admin/assets/*`; `caddy_data`/`caddy_config` переживают пересоздание.
- **Документация:** прод-деплой-гайд (одноразовая настройка `rclone.conf`, переменные, запуск);
  синк корневого `CLAUDE.md` (бэкенд теперь реальный) + `front/CLAUDE.md` при необходимости +
  записи в памяти проекта.

## Инварианты / ограничения
- В рантайме по-прежнему только `caddy`+`back`+`minio` (никаких билдеров).
- Ничего не ломать в уже принятых задачах; только финализация/харднинг/доки.

## На что НЕ замахиваться
Новая функциональность. Только надёжность, безопасность, документация, проверка целого.
