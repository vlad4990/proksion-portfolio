# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev      # Vite dev server → http://localhost:5173
npm run build    # tsc --noEmit (type-check) + vite build → dist/
npm run preview  # serve the production build locally
```

Для отладки в Chrome (MCP) запускай dev на 5005: `npm run dev -- --port 5005` (расширение пользователя разрешает только этот порт).

Нет тестов, линтера и форматтера. Проверка корректности — `npm run build` (он же гоняет `tsc --noEmit` в strict-режиме с `noUnusedLocals`/`noUnusedParameters`).

Весь UI и контент — на русском; сохраняй язык при правках. Display-заголовки — в верхнем регистре.

## Stack

SPA на **Vite 6 + React 18 + TypeScript strict**. Зависимостей минимум: `react`, `react-dom`, `react-router` (7.x) и `react-masonry-css` (~2 КБ, без транзитивных зависимостей; собственные TS-типы — листинг тайлов проектов). Никаких UI-библиотек и CSS-фреймворков — своя дизайн-система на CSS-токенах. Точка входа — `src/main.tsx` (`BrowserRouter` → `App`).

**Данные — из API** (`src/api/`: `client.ts` тонкие fetch-обёртки, `types.ts`, `status.ts` (`LoadStatus`), хуки `useCategories`/`useWorkDetail`/`useTags`/`useFeatured`/`useCategory`/`useInfiniteWorks`). Хуки держат **сессионный кэш** (модульные Map'ы: категории, деталь работы, теги, витрины, категория по слагу, догруженные порции `/works`) — повторная навигация, смена тега и закрытие модалки не перезапрашивают данные и не мигают скелетонами; ревалидации нет (контент меняется редко, свежее — со следующей загрузкой страницы). База — `/api` (в dev проксируется на `back:3001`, в проде Caddy `handle_path /api/*`). Картинки — same-origin `/media/*`. Dev-proxy `/api`+`/media` настроен в `vite.config.ts` (dev-сервер на 5005). Статических массивов контента больше нет.

Эндпоинты редизайна (`docs/projects-redesign.md` §5): `getTags()`, `getFeatured()`, `getCategory(cat)`, `getWorksFiltered({category, subcategory, tag, offset, limit})`, `getWorkBySlug(cat, sub, work)`. `useInfiniteWorks({cat, sub, tag})` — инфинити-скролл: ключ кэша `` `${cat}/${sub}?tag=${tag}` ``, порция 24, `hasMore`/`loadingMore`, и `sentinelRef` — колбэк-ref, который вешает нативный `IntersectionObserver` (rootMargin 600px, отключается при `!hasMore || loadingMore`; новых зависимостей нет). Кэш хранит достигнутый offset, поэтому возврат из модалки и переключение табов не сбрасывают догруженное.

> Исторически фронт был на Astro + React islands; миграция на чистый Vite+React SPA завершена — никаких `.astro`, SSR и `@astrojs/*` больше нет.

## Architecture

Одностраничное портфолио. Ключевые неочевидные решения:

### Роутинг — react-router, по URL

`App.tsx` использует `react-router` (`Routes/Route/Navigate/useLocation/useNavigate`). Активный экран выводится из `pathname` через `pathnameToRoute()`. Маршруты:

- `/` — home (about)
- `/projects` (+ `?tag=<slug>`) — **корневая-обзор** (см. ниже)
- `/projects/:cat` и `/projects/:cat/:sub` — **страница категории** (см. ниже): один и тот же экран, подкатегория = активный таб
- `/projects/:cat/:sub/:work` — **модалка работы** поверх страницы категории (вертикальная лента картинок, шарящийся URL; `Esc`/клик вне/крестик → закрытие). `:work` — **слаг** работы (`GET /works/:cat/:sub/:work`); если сегмент — целое число (легаси-ссылки), деталь грузится по id и `useWorkModal` делает `replace`-редирект на канонический слаговый URL (слаги пути берутся из ответа, история не засоряется). Карусели и `?img=`-слайдов больше нет: все картинки на экране, легаси-`?img` просто игнорируется
- `/contacts`
- `*` — `<Navigate to="/" replace />`

URL реально меняется, история работает. Навигация — **настоящие ссылки** (`<Link>`): десктоп — `TopNav`, мобайл — `MobileTabBar`, крошки/чипы-табы и сами тайлы тоже ссылки (работают cmd-клик/новая вкладка/копирование адреса).

**Закрытие модалки** — шаг назад по истории (`navigate(-1)`), а не переход на `/projects/:cat/:sub`: канонический путь работы всегда содержит подкатегорию, но открыть работу могли и с таба «ВСЕ» (`/projects/:cat`), и с корневой в тег-режиме — из URL модалки исходный листинг не вывести. Пришли ли мы «изнутри» приложения, `useWorkModal` фиксирует на первом рендере (`location.key !== 'default'`; `?img=` делает `replace` и ключ меняет — решение должно остаться прежним). У deep-link'а шага назад нет → `replace` на `/projects/:cat/:sub`.

**Скролл к началу** — эффект в `App.tsx`, привязанный к **ключу листинга** (`useScrollKey`), а не ко всему `pathname`. Пока открыта работа (путь из 4 сегментов), ключ держится равным последнему НЕ-модальному пути — по той же причине, что и выше: открытие/закрытие работы и карусель `?img=` скролл листинга не сбрасывают, откуда бы работу ни открыли; смена раздела/таба/страницы — сбрасывает. Повторный клик по уже активному пункту (URL не меняется → эффект молчит) докручивается плавно в самих nav-компонентах (`TopNav` + `MobileTabBar`) через общий `smoothScrollTo` из `src/lib/scroll.ts` — одинаково в обоих деревьях.

### Двойное дерево компонентов (не адаптив через CSS)

`App.tsx` через `useIsMobile()` (хук на `matchMedia('(max-width: 767.98px)')`) выбирает **одно из двух полностью отдельных деревьев** — `components/desktop/*` или `components/mobile/*`. Это не один отзывчивый layout: десктоп и мобайл — разные компоненты с разной разметкой. Любую фичу, затрагивающую обе платформы, нужно реализовывать в обоих деревьях (напр. `ProjectsScreen.tsx` + `MobileProjects.tsx`, модалка `WorkModal.tsx` + `MobileWorkModal.tsx`, футер `desktop/ProjectsFooter.tsx` + `mobile/ProjectsFooter.tsx`). Данные оба дерева тянут из общих API-хуков (`src/api/`), а не из дублированных статических массивов.

**`components/shared/`** — общие атомы БЕЗ развилок разметки, одинаковые в обоих деревьях; платформа передаётся пропом `mobile` (он лишь переключает класс с `--*-mob`-токенами). Сейчас там `FilterChip` (label + count, active/inactive; полиморфный — с пропом `to` рендерится `<Link>`, с `onClick` — `<button>`), `Badge` (бейдж в hairline-рамке с произвольным содержимым — счётчики, срок работы, «2 СТУПЕНИ»; **высота** — `--badge-h`/`--badge-h-mob` = 29/24 из макета, а не паддинг × лидинг: бейдж всегда однострочный, и при нашем 1px-border внешняя рамка обязана совпасть с дизайном. Обёртка бейджа должна быть flex-контейнером — иначе вокруг inline-элемента остаётся люфт от strut. Верхний паддинг `--badge-pad-top(-mob)` — не отступ макета, а **оптическая компенсация**: em-box Kanit асимметричен, и `align-items: center` центрирует строку, а не сами литеры, поэтому текст уезжает вверх на ~2.5px; паддинг сдвигает строку на половину своей величины, значения подобраны замером cap-height против baseline) и `CountBadge` (тот же `Badge` + плюрализация «68 РАБОТ» из `lib/format.ts`). Всё, что требует разной вёрстки на платформах, в `shared/` не кладём.

Общие хелперы — `src/lib/`: `format.ts` (`formatUpdated('2026-07-15…') → «ИЮЛЬ 2026»`, `pluralizeWorks`/`formatWorksCount`, `pluralizeSections`/`formatSectionsCount` → «05 РАЗДЕЛОВ»), `contacts.ts` (**единственный** источник email/Telegram/Behance/CV и текстов футера — читают и `/contacts`, и футеры; строки не дублировать), `about.ts` (**единственный** источник контента «Обо мне»: лид, пилюли навыков, опыт, образование — тексты в дизайне на десктопе и мобайле совпадают, дублировать нельзя), `scroll.ts`, `links.ts` (канонические URL: `workHref`/`categoryHref`/`subcategoryHref`/`tagHref` — ссылки не собираем строками по месту), `showcase.ts` (раскладка кураторских витрин по вариантам — чистые функции для обоих деревьев).

### Главная `/` — «Обо мне» (дизайн: фреймы `P6kgA` / `q7llNK`)

`AboutSection.tsx` (desktop) и `MobileAbout.tsx` (mobile) — страница за занавесом-героем. Контент статический (`lib/about.ts`), API не задействован.

1. **Hero-сплит** — desktop: слева лид (`--t-body`, lh 1.5) + «ЧЕМ ЗАНИМАЮСЬ» и пилюли навыков, справа кадр фото (`aspect-ratio: 556/427` из макета держит место в потоке, фото прижато к верху и центрировано). **Окно обрезки — отдельный слой `.photoClip`**, продлённый вниз на `--sp-block-sm`: по просьбе заказчика фото доходит до hairline первой секции, тогда как в макете под кадром 48px воздуха. Кадру дан `align-self: stretch` — на 768–1099 текстовая колонка выше кадра, и без растяжки под фото оставалась дыра до 240px; пропорция макета работает как минимальная высота. Фото покрывает окно на всех тирах с запасом (отрисованная высота 833–1391 против окна 384–630). Mobile: титул «ОБО МНЕ» + лид, затем пилюли, затем кадр фото (`346/294`). Титула на десктопе нет — так в макете (узел «Title Row» выключен).
2. **Пилюли навыков** — `ABOUT_SKILL_ROWS` (4 + 4): на десктопе ряды заданы явно, потому что по ширине колонки пятая пилюля влезла бы в первый ряд и разбивка макета сломалась бы; мобайл раскладывает `ABOUT_SKILLS` (тот же набор плоским списком) переносом строк. Первый ряд макета на мобайле шире контентных 346px, поэтому там рядов больше, чем в макете — это осознанно.
3. **Секции «ОПЫТ РАБОТЫ» / «ОБРАЗОВАНИЕ»** — голова: глиф-курсор (`assets/icon-marker-pixel.svg`) + титул (`--t-section`) + `shared/Badge`, справа мета-строка (на узком тире уходит под титул). Работа: слева компания (`--t-header-2`, `--accent`, прошлая — `--accent-dim`), роль (`--t-label`), бейдж срока; справа буллеты в две колонки (`columns: 2`, порядок чтения сверху вниз; на тире 768–1099 — одна колонка: макет нарисован для ≥1400, в двух узких колонках остаётся по два-три слова в строке). Образование: степень (`--t-sub-section`) + учебное заведение (`--t-label`/`--t-job-role-mob`, `line-height: 1.4` на **блочном** элементе — см. про strut в «Styling»), между записями hairline-soft; вертикальные паддинги записей — из макета (десктоп 8/32 и 32/32, мобайл 4/20, 20 сверху и 24 у последней).
4. **Футер** — тот же `ProjectsFooter` своего дерева. В макете «Обо мне» CTA-заголовок выключен, но компонент футера общий и по договорённости не менялся — заголовок остаётся.

Шапка/мини-хедер и футер — общий хром: они **сознательно оставлены как были** и не приводились к макетам (в дизайне у шапки другой вордмарк, красный активный пункт и чип «ОТКРЫТ К ПРОЕКТАМ», на мобайле — 56px-хедер + статус-бар). Мобильный статус-бар из фрейма тоже не делаем — та же договорённость, что на `/projects`.

### Корневая `/projects` — обзор разделов (задача 18)

`ProjectsScreen.tsx` (desktop, фрейм `tVnqG`) и `MobileProjects.tsx` (mobile, фрейм `N8NrSi`) — **не общий листинг**, а обзор: сайдбар и «Показать ещё» удалены.

1. **Hero** — оверлайн, «ПРОЕКТЫ» + красный квадрат, подзаголовок (тексты — константы компонента) и 3 стата справа/в ряд: сумма `work_count` категорий, число категорий, константа «3 ГОДА». Пока категории грузятся, в счётчиках прочерк, а не нули.
2. **Ряд чипов-тегов** — `shared/FilterChip`-ссылки: «ВСЕ &lt;total&gt;» → `/projects`, тег → `/projects?tag=<slug>` (активный определяется `useSearchParams`). Пустой `/tags` → весь ряд (вместе с подсказкой) скрыт. Справа — кнопка «NN РАЗДЕЛОВ ↓», плавный скролл к первой секции (`smoothScrollTo` + компенсация `--nav-h`).
3. **Секции категорий** (порядок `/categories`) — голова (номер `01`, титул, `CountBadge`, описание/мета, «ВСЕ РАБОТЫ ↗» → `/projects/:cat`) + витрина из `GET /featured` по `category.display_variant`:
   - `showcase` — ряд A (hero с пилюлей-подписью = title работы + до 2 тайлов) и ряд B (до 4 тайлов); mobile — hero во всю ширину + пары;
   - `strip` — один ряд: до 4 работ, при 5+ ряд плотнее (и потому ниже); mobile — пары (≤4) либо тройка (5+);
   - `cards` — карточки (превью с натуральной пропорцией + title/description работы + мета раздела + «СМОТРЕТЬ КЕЙС ↗» в модалку); desktop — сетка 2 колонки, mobile — столбик.
   Раскладка «сколько работ куда» — чистые функции `lib/showcase.ts` (`splitShowcase`/`stripWorks`/`cardWorks`/`isDenseStrip`/`chunk`), одни на оба дерева. Витрины — **выровненные ряды (justified), без обрезки картинок**: слот несёт inline `aspect-ratio` и `--ar` (= w/h из API), ряд — flex с `flex-grow: var(--ar)` — ширина слота ∝ пропорциям картинки, высота ряда выводится сама (скелетоны — классы `.skel*` с пропорциями-заглушками). Ссылки — канонические (`lib/links.ts`).
4. **Тег-режим** (`?tag=`) — вместо витрины в каждой секции masonry-грид работ категории с тегом (`useInfiniteWorks({cat, tag, limit: 24})`, без сентинела: дальше «ВСЕ РАБОТЫ ↗»). Секции с 0 совпадений не рендерятся вовсе; когда пусты все — состояние «По этому тегу работ пока нет» + сброс на «ВСЕ». Каждая секция сообщает свой счётчик наверх ключом `тег:категория`, поэтому переключение тегов не путает состояния.
5. **Футер** — `ProjectsFooter` своего дерева. Плюс skeleton-состояния (головы + слоты тоном `--c-skeleton`) и текстовые ошибки — белых экранов нет.

Токенов высот слотов витрин больше нет (высоты выводятся из пропорций картинок); тировым остался только `--t-projects-hero` (ступени в 1100–1399 и 768–1099).

### Страница категории `/projects/:cat[/:sub]` (задача 19)

`CategoryScreen.tsx` (desktop, фрейм `h16xA`) и `MobileCategory.tsx` (mobile, фрейм `fQvBp`) — второй уровень листинга. Один экран на оба URL: `/projects/:cat` = таб «ВСЕ», `/projects/:cat/:sub` = таб подкатегории. **URL — единственный источник правды состояния табов** (прямые ссылки и F5 работают, чипы — `<Link>`).

1. **Крошки** — панель с нижней hairline-soft: «ГЛАВНАЯ» → `/`, «ПРОЕКТЫ» → `/projects`, текущая — `--fg-strong` bold без ссылки; справа «ОБНОВЛЕНО — <`formatUpdated(updated_max)`>» (нет даты — узла нет). На мобайле «ОБНОВЛЕНО» нет — так в дизайне (в 390px не влезает).
2. **Голова** (`GET /categories/:cat` через `useCategory`) — оверлайн «// РАЗДЕЛ NN — <kicker>» (NN = `sort_order + 1` с ведущим нулём, совпадает с нумерацией секций корневой; без kicker'а — только номер), Title Row (`--t-header-1` + красный квадрат + `CountBadge`), описание `description_long || description`; справа мета-роль, период и «НАПИСАТЬ ПО ПРОЕКТУ ↗» → `/contacts`. NULL-поля пустых узлов не рендерят.
3. **Чипы-табы** — `shared/FilterChip`-ссылки: «ВСЕ <work_count>» → `/projects/:cat`, подкатегория (title uppercase + счётчик видимых работ) → `/projects/:cat/:sub`; активный — по URL. Справа (на мобайле — отдельной строкой) счётчик **«ПОКАЗАНО N ИЗ M»**: N = отрисованных тайлов, M = `total` текущего фильтра, обновляется по мере догрузки.
4. **Masonry + инфинити-скролл** — `useInfiniteWorks({cat, sub})`, порция 24; тот же `<Masonry>`-паттерн, что у тег-режима корневой (`BREAKPOINT_COLS`, `--tile-gap(-mob)`, aspect-ratio из `w/h`, `EAGER_TILES` 8/4). Под гридом — пустой div с `sentinelRef` (`IntersectionObserver`, rootMargin 600px); `hasMore=false` → сентинел **размонтирован**, запросы прекращаются. На время догрузки в конец колонок дорисовываются скелетон-тайлы. Кэш достигнутого offset'а в хуке: возврат из модалки и повторный визит таба отдают догруженное мгновенно, холодный таб показывает скелетоны (без мигания тайлами прошлого таба).
5. **Состояния** — skeleton головы и грида, «В этом разделе пока нет работ.» (пустая подкатегория), текстовые ошибки. Неизвестный `:cat` (404 от API) или `:sub`, которого нет в `subcategories`, → `<Navigate to="/projects" replace />`. Коллизия слагов (`uiux-keysy/boytsovskiy-klub` — и подкатегория, и работа) не стреляет: 3 сегмента — всегда подкатегория, работа живёт на 4-м.
6. **Футер** — `ProjectsFooter` своего дерева.

Заголовок вкладки — `categoryTitle()` из `src/seo.ts` («KUPIKOD — PROKSION»). Эффект пропускает установку, пока определён параметр `:work` (заголовок за модалкой) — иначе `replace`-канонизация легаси-URL затирала бы название работы; при закрытии модалки заголовок раздела возвращается сам.

### Листинг проектов — masonry (react-masonry-css)

Блок `data-test="projects-tiles"` (тег-режим корневой и страница категории, в обоих деревьях) раскладывает тайлы через `<Masonry>` (Pinterest-стиль, распределение слева-направо). Число колонок задаётся `breakpointCols` (JS, по ширине окна): десктоп `{ default: 4, 1399: 3, 1099: 2 }` (повторяет тиры токенов), мобайл `{ default: 2 }`. Зазоры — токены `--tile-gap` / `--tile-gap-mob`; CSS-паттерн библиотеки: контейнер `.masonry` (`display:flex`, `margin-left: -gap`), колонки `.masonryColumn` (`padding-left: gap`), тайлы — `margin-bottom: gap`. `<Masonry>` обёрнут во внешний `<div data-test="projects-tiles">`, т.к. типы библиотеки не пробрасывают произвольные `data-*`. Картиночный тайл — **`<Link>` вокруг `<TileImage>`** (общий лист `components/TileImage.tsx`: `<picture>` avif/webp/jpg; thumb-варианты приходят в тайле из API; картинка целиком, без обрезки; класс `.tile` на ссылке — ховер, скелетон-тон живёт на `.tilePicture:not([data-loaded])` и снимается после загрузки). Натуральные размеры `w/h` → `aspect-ratio` резервирует место заранее (нет скачков layout при загрузке). Первые тайлы (`EAGER_TILES`: 8 десктоп / 4 мобайл) грузятся `loading="eager"` + `fetchpriority="high"` — это LCP листинга; остальные — `loading="lazy"` + `decoding="async"`, под ними до загрузки skeleton-тон `--c-skeleton`. ⚠️ `react-masonry-css` распределяет тайлы по индексу (порядок чтения, баланс по числу элементов), **не** по измеренной пиксельной высоте — при сильном разбросе высот низы колонок не выравниваются идеально (компромисс выбранной библиотеки). Каждый тайл — настоящая ссылка на канонический `/projects/:cat/:sub/:slug` (`lib/links.ts → workHref`; слаги приходят в самом тайле) → модалка работы (`WorkModal`/`MobileWorkModal`) с каруселью поверх листинга. Форма тайла из API — `{ id, slug, title, src, w, h, cat, sub, variants }`.

### Модалка работы — не-фулскрин + FLIP-анимация (без библиотек)

`WorkModal.tsx` (desktop) и `MobileWorkModal.tsx` (mobile); общий контроллер — `useWorkModal` (загрузка детали, Esc, канонизация легаси-id, закрытие = шаг назад по истории с гардами от гонок: повторный close глушится, `finish` после размонтирования не навигирует — иначе browser-back во время анимации закрытия делал бы второй шаг назад).

- **Плейсхолдеры снимаются после загрузки** (`components/WorkImage.tsx`, `components/TileImage.tsx` + хук `lib/useImageLoaded.ts`): пока картинка грузится, под ней тон `--c-skeleton` (CSS-селектор `:not([data-loaded])`) и фон-картинка (thumb тайла / LQIP); как только `<img>` загружена — тон и фон СНИМАЮТСЯ (у модалки с задержкой 260ms, чтобы перекрыть проявление). Иначе у работ с прозрачным PNG-фоном подложка просвечивала сквозь прозрачные зоны молочной дымкой — картинка выглядела «пережатой». Флаг загрузки привязан к **URL источника** (`variants.jpg`), а не к жизни экземпляра: если тот же узел получит другую картинку (позиционное переиспользование — hero-слот витрины рендерится без key), скелетон возвращается тем же рендером. Пустые заглушки-скелетоны (тайл/слот без картинки) носят собственный класс `.fillSkeleton`.
- **По умолчанию — вертикальная лента** (`flex-col`, gap `--tile-gap(-mob)`), первая картинка eager, остальные `loading="lazy"`. Слайд-состояния `?img=` больше нет (легаси-ссылки его игнорируют); горизонтальная карусель — только опционально флагом работы, см. «Карусель на десктопе» ниже.
- **«Единое полотно»** — работа с `WorkDetail.seamless` (чекбокс в админке) рендерит ленту **без зазора**: класс `.imagesSeamless` (`gap: 0`) в обоих деревьях. Соседи перекрываются на `margin-top: -1px` — дробные высоты (aspect-ratio на нецелой ширине колонки) иначе оставляют hairline-щели, и «полотно» рассыпается на полоски.
- **«Карусель на десктопе»** — работа с `WorkDetail.carousel` (чекбокс в админке) при 2+ картинках рендерит в десктопной модалке `WorkCarousel.tsx` вместо ленты: центральный слайд по центру экрана (все слайды одной высоты = вьюпорт − мета; ширина по аспекту, кап по `--modal-edge-x`, позиции — инлайн-марджины + `transform: translateX`; перелистывание — WAAPI-спринг по всем слайдам, ⚠️ НЕ CSS-transition на transform: постоянно промоутнутый transition-слой не перерастеризуется после загрузки картинки внутри — слайд оставался невидимым до любой инвалидации), соседи виднеются у краёв в **ступенчатом градиентном блюре** (`BlurSlices`: N срезов блюр-копии картинки с растущими к краю экрана радиусом/плотностью, ступени распределены по видимой части соседа + хвост полного блюра; оверлей центрального гаснет transition'ом opacity). ⚠️ Блюр сознательно БЕЗ `mask-image` и БЕЗ `backdrop-filter` — Chrome-композитор рисует маскированные/backdrop-слои с неверной геометрией (слайды пропадали, копии двоились не на своих местах); только `overflow` + `filter: blur` + `opacity`. Навигация: стрелки поверх блюра, клик по соседнему слайду, колесо (вертикальную дельту читаем как горизонтальную; порог 60 + кулдаун 550ms гасят инерцию трекпада), горизонтальный свайп трекпада, ←/→. Открытие — тот же FLIP из тайла (центральный слайд), при поздних данных — fade; закрытие — обратный полёт в тайл ТОЛЬКО с первого слайда (`carouselIndexRef`), иначе угасание; оснастка помечена `data-caraux`/`data-carslide` и гаснет в `runClose`. Мобилка и работы с одной картинкой флаг игнорируют — лента как раньше.
- **Desktop — НЕ фулскрин**: затемнение `--backdrop` + прозрачный центрированный диалог. Есть доп. картинки → `flex-row` (мета справа, `--modal-meta-w`), одна → `flex-col` (мета снизу). Размер задаёт ПЕРВАЯ картинка: высота ≤ `100dvh − 2·--modal-edge-y`, ширина ≤ `100vw − 2·--modal-edge-x` (в row-режиме с метой поля считаются для диалога целиком); аспект строгий, реализовано формулой `min()` в CSS от инлайн `--first-ar` (w/h из API). Скролл — по overlay (лента уходит за верх окна), центрирование — `margin: auto` (не flex-center: он делал бы верх недосягаемым). Мета: серый `--bg-panel`, паддинг/gap `--modal-meta-pad`, черта между тайтлом и описанием — full-bleed через отрицательные маргины. Красный крестик — absolute СНАРУЖИ диалога справа-сверху (`right: -56px`).
- **Mobile — фулскрин**: статичный `.root` (перехватывает клики до размонтирования) + шторка `.sheet`, слайд снизу вверх; лента + мета внизу.
- **Анимации — рукописные** (`lib/spring.ts`): симуляция пружины → массив WAAPI-кейфреймов (`linear`-интерполяция), играет на компоузере без ререндеров; motion/framer сознательно НЕ добавлены (≈30 КБ gzip ради того же). Открытие: FLIP из тайла листинга (`lib/flip.ts` — capture-слушатель кликов по ссылкам работ снимает **СНИМОК** rect/thumb/аспекта картинки тайла: живой узел к layout-effect'у модалки может быть пересоздан реконсиляцией листинга под модальным маршрутом, а пиксели на экране ещё прежние; thumb из кэша идёт фоном-плейсхолдером первой картинки) → мета выезжает из-под картинки со сдвигом колонки (если данные пришли позже FLIP — сдвиг меряется по фактическому скачку layout-позиции диалога через `offsetLeft/Top`) → доп. картинки вылетают вниз со stagger и убывающим z-index → параллельно фон/крестик. Закрытие: обратный полёт первой картинки в живой тайл, найденный заново по канонической ссылке (`findLiveTile`), иначе угасание. Эффект открытия под гардом `openedRef` — StrictMode-повтор замерил бы rect с уже применённым первым кадром FLIP и заместил бы полёт вырожденной анимацией. `prefers-reduced-motion` отключает всё. Deep-link (без источника) — мягкое появление диалога.
- **Прогрев до клика** (`lib/prefetch.ts`): делегированные `pointerover`/`touchstart`/`focusin` по ссылке работы → `prefetchWorkDetail` (в тот же сессионный кэш, что читает `useWorkDetail`) + скрытый `<picture>` прогревает full-вариант первой картинки в HTTP-кэш (браузер сам качает свой формат avif/webp/jpg) — модалка открывается без сети и без пустоты.

### Занавес-герой (hero curtain)

Hero — это **fixed-оверлей поверх всего** (z-index 1000), а не первая секция. Управляется `heroPhase` (`'visible' | 'dismissing' | 'gone'`). Показывается **только при свежей загрузке пути `/`**; deep-link на `/projects` и т.п. инициализирует `heroPhase` сразу в `'gone'` (занавес пропускается). Любой первый ввод (`wheel`/`touchstart`/`keydown`) или клик запускает `dismissHero()` → CSS `translateY(-100%)` → через 600ms `heroPhase` → `'gone'` и оверлей удаляется из DOM. Пока занавес поднят, скролл документа заблокирован (`documentElement.style.overflow = 'hidden'`).

## Styling — CSS Modules + tokens (строго)

- **Единственный глобальный CSS** — `src/styles/tokens.css`: `@font-face`, сброс и все дизайн-токены как CSS Custom Properties в `:root`. Компоненты читают их через `var(--token)`. Шрифты лежат в `public/fonts/` (`Stengazeta-Regular.ttf`, `Kanit-Cyrillic.ttf`), пути в `@font-face` абсолютные `/fonts/...`.
- Каждый компонент — пара `Name.tsx` + `Name.module.css`. **Никаких инлайн-стилей и хардкода цветов/размеров.** Единственное допустимое инлайн-исключение — данные тайлов проектов (высота/картинка/цвет), которые приходят из массива.
- **`line-height` на многострочном тексте требует блочного элемента.** Глобально `body` = `--t-body`/`--lh-body` (22px/1.25 = 27.5px), и у **inline**-элемента (`<span>` вне flex-контейнера) высота строки берётся от strut родителя, а не от собственного `line-height` — текст в две строки растягивается. Такому тексту ставим `display: block` (так починен вуз в «ОБРАЗОВАНИИ»). Внутри flex/grid-родителя проблемы нет: `<span>` там становится блочным айтемом.
- **Пилюли (чип, бейдж) — высота токеном + оптическая компенсация.** У однострочных элементов в рамке высоту задаём из макета (`--chip-h(-mob)` 39/37, `--badge-h(-mob)` 29/24), а паддинг оставляем только горизонтальным: «паддинг × лидинг» с дизайном не сходится (наш 1px-border занимает место, а в макете stroke — нет), да и сам макет рвётся — там чипы 37 и 39 в одном ряду, потому что автолидинг реагирует на «Й», латиницу и цифры. Плюс `align-items: center` центрирует строку, а не литеры: em-box Kanit асимметричен (ascent 10 / descent 4 при 13px), и текст уезжает вверх на ~2.5px — это лечит верхний паддинг `--chip-pad-top(-mob)` / `--badge-pad-top(-mob)` (сдвиг = половина паддинга). Значения подобраны замером cap-height против baseline; **в `em` они не масштабируются** — при другом кегле/высоте рамки нужен свой пиксель. Проверять именно по cap-height и baseline: bounding box строки врёт, у «Д»/«Ц»/«Щ» в Kanit есть ножки ниже baseline.
- `src/styles/layout.module.css` — общая центрированная колонка `.page` (fluid-ширина до `--page-max`, фиксированные гаттеры по тиру). `src/App.module.css` — chrome: оверлей-занавес, fixed nav-host, stage.

### Респонсив — токеновые тиры, без scale/clamp

Часть токенов — **компонентные, вне тиров** (в дизайне это литералы): `--t-overline/-label/-chip/-meta/-desc/-lead`, `--chip-h(-mob)`/`--chip-pad-x(-mob)`, `--badge-h(-mob)`/`--badge-pad-x(-mob)`, `--*-pad-top(-mob)` (оптические компенсации, см. ниже), `--tile-caption`, `--cta-btn-pad`/`--cta-btn-h-mob` (блок «КОМПОНЕНТНЫЕ размеры» в `:root`; в дизайне это блок **08** фрейма ДС `ZRSQk`), а также токены модалки `--modal-meta-w`/`--modal-meta-pad(-mob)`/`--backdrop`. Их не нужно дублировать в медиа-блоках. А вот `--t-projects-hero` и поля модалки `--modal-edge-y`/`--modal-edge-x` (база 100/200) — **тировые**: заданы в `:root` (≥1400) и переопределены в обоих desktop-медиа-блоках. Высоты слотов витрин корневой `/projects` токенами не задаются — они выводятся из пропорций картинок (justified-ряды).

Размеры не «резинятся». `tokens.css` переопределяет набор токенов в тирах: база в `:root` (`≥1400`), `@media 1100–1399.98`, `@media 768–1099.98`, и `<768` — мобильное дерево, использующее токены с суффиксом `--*-mob` (заданы в `:root`). Внутри тира всё фиксировано; fluid остаётся только ширина контентных колонок. Чтобы поправить размеры — меняй токены в нужном медиа-блоке `tokens.css`, не добавляй `transform: scale()` или `clamp()` в компонентах.
